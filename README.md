# 晨充 · Neptune Hub

面向同学共享的尼普顿充电预约工具。当前已实现云端原型源码；用户随后提出数据留本地，现正在核对本地执行方式与 iPhone 快捷指令的可行性。

这是独立的新项目，基线来自已经现场成功的 [`neptune-charge-scheduler`](../neptune-charge-scheduler/README.md)。旧项目、本人加密账号、运行日志、Windows 任务和桌面入口均未迁移或修改。Gemini 参与前端生成的模型与提示词记录见 [来源记录](./docs/gemini-frontend.md)。

## 同学的使用方式

1. 在发布的网站注册并登录自己的账户。邮箱确认邮件需要管理员配置自定义 SMTP；Supabase 默认邮件服务仅面向组织成员，不能直接用于同学开放注册。[官方说明](https://supabase.com/docs/guides/auth/auth-smtp)
2. 在微信扫描尼普顿插座二维码，打开付款页，复制完整链接，在网站首次绑定。网站只解析账号和设备信息，固定访问已验证的官方接口，不访问用户输入的任意地址。
3. 为常用充电点设置名称、8位设备编号和插座号；可保存多个点位。
4. 接好自己的车和充电器，选择1分钟后至24小时内的时间，核对目标并勾选确认，再提交一次预约。所有时间按北京时间显示。
5. 预约生效后可以关闭网页。执行前30秒之外可以取消；开始核对或提交后应到微信查看订单。结果不明时，先在微信确认，再在页面解除预约锁。

星期设置提供未来安排建议，每次实际预约仍需要确认车辆已接好。公共插座无法证明连接的是哪辆车，不提供无人确认的每天循环开电。

## 支持的充电范围

当前只支持已核对的计量收费、余额支付、“充满自停”最长480分钟套餐。设备、账号、实名要求、六项费率、预扣金额、插座状态及已有订单都要核对。预扣上限可设为0.01–2.00元；超出设置或平台条件变化会停止。

“6点启动”并不承诺9点停止或充满。执行流程在指定时间后尝试等待恢复营业，并等待设备30秒，超过10分钟窗口停止。平台网络与云调度没有秒级准点承诺。不自动充值、不调用微信支付、不结束已有订单。

新建开电请求前，数据库原子记录提交占用，只有一个执行者可以成功。提交结果丢失时不重新创建请求；确认查询只复用原请求标识。结果不明会锁定该账号及插座，防止用户再次预约造成重复付款。

## 本地开发

Node.js 22，安装项目固定版本依赖：

```powershell
npm ci
npm run dev
```

打开 `http://127.0.0.1:3086/`。需要配置 `.env.local` 中的公开 Supabase URL/Key、服务端 Secret/Service Role Key、稳定的32字节 Base64 `ACCOUNT_ENCRYPTION_KEY`。`.env.local`、本机测试凭据、工作流缓存及验证产物全部被 Git 忽略。

`/setup` 只在本机开发服务接收服务端密钥，先验证数据库权限再保存；生产环境返回404。`/dev-preview` 仅用于开发环境的离线界面验证，不触发平台请求，生产环境同样返回404。

```powershell
npm run typecheck
npm test
npm run build
npm audit
```

测试覆盖平台参数、身份/租户隔离、夜间预约、收费变化、重复提交、提交响应丢失、原标识确认、冻结配置、取消竞态、结果不明锁定和账号密文所有者隔离。测试不调用真实充电接口。

## 云端配置与部署

本项目已创建的资源：

- Supabase：`qnvtuuwvloddxvhmppcd`，新加坡；结构见 [`db/schema.sql`](./db/schema.sql)。数据表开启 RLS，浏览器角色无直接读写权限，服务端鉴权后按本人用户ID访问。
- Vercel：`neptune-charge-hub`，`ballcards-projects` 团队，项目 `prj_PJg7An8MF91H8fBQ3ADsCXRkyfOm`，新加坡 `sin1`，Node.js 22、Fluid compute 与系统环境变量已启用。

生产环境需要 `.env.example` 列出的设置。公开URL/Key使用普通环境变量，服务端密钥和加密密钥使用敏感变量；不要上传 `.env.local`。已经保存账号后不可随意换加密密钥，否则旧密文无法读取。

首次部署保持 `CHARGING_ENABLED=false`。用 `/api/diagnostics` 启动无付款的5秒持久调度和公共设备只读探测，确认云端数据库、工作流及尼普顿网络连接；验证通过后再启用预约开关。自检记录与业务结果独立保存，不依赖平台短期日志。

分享前还需确认生产域名允许同学访问，并配置 Supabase Auth 的网站URL/重定向URL和自定义 SMTP。应用自己的登录和账号隔离始终保留。

本机 Vercel CLI 的 Unicode 主机名问题使用 [`scripts/vercel-cli.mjs`](./scripts/vercel-cli.mjs) 进程内兼容，不修改全局安装或登录。源码打包与云端检查脚本见 `scripts/`；仅上传已审阅的源码白名单，绝不包含本机配置。
