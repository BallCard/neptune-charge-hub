# 浏览器身份与历史认证邮件

## 当前免注册流程 · 2026-10-21

用户已用免注册方案替代下文Gmail注册方案。只查端口不创建身份；首次进入预约、记录或设置时调用Supabase匿名身份并将会话保存在当前浏览器。已有邮箱会话直接沿用。每次业务请求仍由服务端验证用户和有效会话，并以服务端user_id限定数据，匿名用户不能访问私有业务表、RPC或调度。静态网页不包含或预渲染用户状态。

清除网站数据、无痕模式或换设备无法自动找回原身份，已生效云端预约仍执行。身份失效时只提示核对，不自动替换；明确确认后才可重建。没有恢复码或跨设备恢复。设置页仅保留折叠的旧邮箱账号恢复，已绑定付款授权或存在记录的匿名身份禁止直接切换，不合并或复制预约。

Supabase设置为`external_anonymous_users_enabled=true`与`disable_signup=false`，保留每IP每小时30个新匿名身份的原限额。总注册开关也控制匿名创建，故不能直接关闭；注册前钩子`public.web_before_user_created`只接受Auth提供的`user.is_anonymous=true`，新邮箱注册返回403，忽略user_metadata中的自称匿名。函数仅supabase_auth_admin可执行，客户端无权限。旧账号的邮箱确认与密码登录保留。原Gmail SMTP和本机DPAPI配置只作历史保留，新流程不发送注册/找回邮件。

下文为被替代方案的历史配置记录，不再作为新用户前置条件。当前上线与测试状态见README和CHANGELOG。

本轮安全顾问核对：5张业务表RLS均开启且客户端无私有表/RPC权限。新增匿名身份提示涉及pg_cron默认的两条PUBLIC策略；进一步查询确认authenticated没有cron schema的USAGE权限、没有job写权限，业务API也不暴露cron。保留该顾问提示，不为消除告警开放权限或改动唯一调度。旧密码账号的泄露密码保护WARN仍存在，不视为已解决。手机真机、校园网络和现场开电仍需本人验收。

## 此前邮箱注册方案

2026-10-21：按用户要求准备开放所有同学注册、登录及各自管理预约。魔搭校园版保留逐次会话验证、服务端 user_id、私有表权限、用户限流和原唯一分钟调度。个人版构建与回退产物继续保留。

注册和找回密码使用邮件中的8位验证码，在原页面完成验证，不依赖魔搭外层iframe传递回跳链接。邮箱必须先确认，不能通过关闭确认来绕过邮件配置。找回密码后设置新密码并退出会话，重新登录。每人必须手动导入本人付款授权；不能共享晨充账号或付款链接。

## Gmail 发件配置

1. 创建仅用于晨充的普通 Gmail 账号；开启两步验证，在 Google 账号安全设置生成名为“晨充认证邮件”的应用专用密码。不要使用 Google 登录密码。若学校/组织账号没有该选项，需换可用账号或其他发件服务。
2. 在本项目 PowerShell 7 执行 `pwsh -NoProfile -ExecutionPolicy Bypass -File .\scripts\set-auth-smtp.ps1 -Provider Gmail`，也可让 Codex 直接打开输入窗口。邮箱在本机填写，应用专用密码隐藏输入；只将完整配置以 Windows DPAPI 加密保存到已忽略的 `.local/auth-smtp/config.dpapi`，不进入源码或公开部署。该命令只保存本机配置，不发送邮件或开启注册。脚本先核对安全模块，避免继承模块路径的旧版 Windows PowerShell 在输入后才失败。
3. 部署前测试 SMTP TLS/认证，随后通过 Supabase 管理接口将 `smtp.gmail.com:465`、项目发件邮箱和应用专用密码写入服务端 Auth 配置；发件人名称使用“晨充”。发送限额先保持每小时30封、同邮箱至少60秒一次，邮箱确认保留，验证码8位、有效期10分钟。只在发信和校园版验收通过后开启公开注册。
4. 用自有可收信测试地址验证注册邮件、验证码、登录、找回密码和旧密码失效。测试记录不得保存验证码、密码、会话或收件地址；清理临时用户及会话。非本人现场确认不得测试真实开电。

普通 Gmail 无需购买域名或 Workspace；邮件数量与风控受 Google 限制，不视为业务发信保证。官方提示一天超过500封邮件可能暂时无法发信；先保守限额，实际送达需测试 QQ、校园邮箱等收件端。已有本机 Google OAuth 登录不等于 Supabase SMTP 凭据。修改 Google 账号密码可能撤销应用专用密码，需要重新配置。

官方依据：[应用专用密码](https://support.google.com/accounts/answer/185833?hl=zh-Hans)、[Gmail 发信限制](https://support.google.com/mail/answer/22839?hl=zh-Hans)、[Supabase 自定义SMTP](https://supabase.com/docs/guides/auth/auth-smtp)、[密码与找回流程](https://supabase.com/docs/guides/auth/passwords)。

## 验收边界

邮件限额、防刷和预约容量相互独立。当前每分钟最多领取2笔预约，保留既有保守容量准入、同账号/同插座唯一活动计划、数据库先消费后开电及结果不明冻结。开放注册不代表无限预约或物理插座占位。

公开注册上线状态、当前发行、实测结果以 README 和 CHANGELOG 最新记录为准。手机真机、校园网络及真实扣款开电仍需现场验收。
