# 并发、安全与恢复核验（2026-10-14）

本轮为本地实现与隔离验证，数据库迁移及新版接口尚未发布线上。结论：防重复提交、数据库竞争与权限隔离有可重复的测试依据；仍是小规模个人测试版，不构成公网容量或完整安全认证。

## 修改

- 调度每分钟最多领取两笔并行执行，沿用数据库租约和先消费后提交保护。单笔失败不重试新请求；调度返回503并保存汇总失败数，不再吞掉异常后返回正常。
- 心跳在完成本轮工作后更新，写入时不覆盖管理员同时关闭的开关。最近失败、缺少完整状态、心跳超过三分钟或最老到期任务积压两分钟，均停止接受新预约；健康检查返回503。调度本身继续处理恢复任务。
- 数据库串行化容量检查：新预约时间前后各十分钟，已有未结束预约达到4笔时拒绝新增。相同幂等标识的重试仍能取回原记录。这是给核对/恢复留余量的保守准入阈值，**不是保证4人准点成功的容量承诺**；不会取消已有记录。
- 用户限流由数据库原子更新实现，多实例共用：每个自然分钟，状态查询60次、上游核对10次、预约10次、取消/人工核对合计20次。超限429及Retry-After；限流异常时停止业务调用。自然分钟边界可能允许两倍短时突发，限流检查本身也会产生数据库访问。
- 运维汇总接口`POST /api/web/operations`使用调度专用凭据，仅返回任务数、积压年龄、结果不明数、过期租约及本轮统计，不返回用户或付款信息。
- 空位查询改用HTTPS，禁止重定向，核对返回设备编号并限制单次响应为1MB。保留15秒缓存、同实例请求合并及最多8路上游读取。

## 验证结果

`npm test`：50项全部通过。覆盖100次重复执行仍只产生一次模拟新开电、丢失数据库提交响应、原请求恢复、取消/租约失效、会话撤销、限流故障、调度失败、健康状态，以及4笔预约在两次临时查询失败下的虚拟时间队列排空。

`npm run test:cloud-isolated`：34项断言通过。创建临时PostgreSQL 16容器，无网络、无宿主端口，不接受远程数据库地址；只使用合成用户和合成加密数据，结束后删除容器。

| 场景 | 结果 |
| --- | --- |
| 同一用户100次并发核对额度申请 | 10次放行，90次限流；取消和其他用户额度独立 |
| 同一标识32次并发预约 | 全部返回同一标识，数据库仅一条 |
| 已有一笔，32名其他用户同时预约 | 3笔新增、29笔容量拒绝，总数4笔 |
| 20个同时运行的任务领取者 | 4笔任务各领取一次，无重复 |
| 32个取消/消费竞争调用 | 仅一方成功；旧租约不能重新消费 |
| 模拟数据备份并恢复到新数据库 | 保留加密原请求和消费标志，恢复后不能重发；客户端仍无表访问权限 |
| 权限、过期任务、运行开关 | 私有表RLS及函数权限通过；超窗不能消费；汇报不重新打开关闭的调度 |

第二轮本机进程端到端P95：限流1135ms、幂等410ms、准入414ms、领取312ms、取消竞争395ms。包含Docker进程开销，**不能换算为Vercel/Supabase生产吞吐或用户容量**。这些是瞬时并发测试，尚未进行数小时持续负载测试。

生产构建及类型检查通过；生产依赖审计0项已知漏洞。使用HTTPS对一台公开设备完成只读核验；浏览器本地加载14个站点、420个插座正常。没有创建真实预约、提交真实开电、读取个人付款配置或发送消息。

## 隔离数据库的边界

应用原始业务迁移和本次迁移均执行。为隔离外部系统，测试用最小`auth`表及合成`vault`实现代替托管环境；`pg_cron`安装和`pg_net`安装被跳过，调度注册为空实现，网络调用函数强制失败。实际使用PostgreSQL锁、约束、角色权限、pgcrypto加密、pg_dump和恢复。

因此，恢复演练验证的是业务数据/权限/消费标志的保存，不等于验证了Supabase托管Vault、生产密钥备份或供应商灾难恢复。真实备份必须同时考虑数据库、Vault依赖和服务凭据，并在**调度关闭、隔离出网**的新环境验证后才能恢复服务。

## 发布顺序与故障处置

1. 先应用`20261014020402_web_capacity_and_limits.sql`，再发布筛选部署包。迁移保留旧接口兼容；新版接口缺少新RPC时会停止业务操作。新版本须等首次调度成功上报后才开放新预约。
2. 用`npm run check:cloud-health`做只读健康检查。失败退出码1，供外部监控接入；**当前没有新增定时监控或消息通知服务**。上线后还须核对真实Cron、受保护运维汇总与云端安全检查。
3. 出现503、积压、过期租约时，查看汇总和持久记录；禁止人工补发`beginCharge`。已消费任务只核对原请求。结果不明时保持限制，由本人微信核对后走现有解除流程。
4. 回滚应用可保留新增限流表及函数，避免破坏记录。不要恢复过期数据库快照覆盖生产消费标志，否则可能丢失防重证据；恢复前必须隔离执行器并逐笔核对。
