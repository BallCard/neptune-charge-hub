# iPhone 快捷指令只读验证

状态：2026-10-07 已完成电脑端公共设备查询；**尚未制作可安装的快捷指令，尚未在用户 iPhone 上运行**。旧版的 Windows 现场成功和新版的手机网页布局检查不能替代这项验证。

先用无账号的短流程检验手机网络与定时触发，再评估 iPhone 能否独立执行本地预约。云端配置与部署暂缓，现有个人 Windows 工具保持原状。

## 第一步：手动查询公共设备

在 iPhone 的“快捷指令”中新建一条，命名为“晨充只读测试”，依次添加下面的操作：

1. **URL**，内容为 `https://www.szlzxn.cn/wxn/getDeviceInfo`。
2. **获取 URL 内容**，输入选择上一步 URL；展开设置，方法设为 **POST**，请求体选 **表单**，添加两项“文本”字段：

   | 键 | 值 |
   | --- | --- |
   | `areaId` | `6` |
   | `devaddress` | `60359118` |

3. **快速查看**，输入选择“获取 URL 内容”的结果。

手动运行一次；如系统请求访问 `www.szlzxn.cn`，按手机提示授权该站点。这里无需输入付款链接、微信账号、密码或开发者云端密钥。该端点只查询设备，不创建充电订单。

成功标准：返回 JSON 中 `success` 为 `true`，`obj` 中 `devaddress` 为 `60359118`。夜间 `isWorkTime` 为 `0` 仍可说明查询成功；它表示未营业，不能当作失败。若返回网页、报错或缺少这些字段，记录提示文字，先停止本项测试。

电脑端对同一端点使用 POST、URL 编码表单，于 **2026-10-07 13:49:25 +08:00** 得到 HTTP 200、`success=true`、设备编号匹配。这仅确认当前接口可达，手机的请求编码、权限和网络仍待验证。

Apple 的“获取 URL 内容”支持 POST 和表单请求体，见[官方请求说明](https://support.apple.com/zh-cn/guide/shortcuts/apd58d46713f/ios)。

## 第二步：锁屏定时查询

手动查询通过后，在该测试指令中把“快速查看”替换成下面的处理；定时流程中不使用需要查看或点按的界面：

1. 从“获取 URL 内容”的结果中，**获取词典值** `success`。
2. **如果**这个值为真：从原查询结果取 `obj`，再从中取 `devaddress`；仅当编号为 `60359118` 时继续。
3. 查询且编号匹配时，取**当前日期**，用**格式化日期**显示日期和时间，再用**显示通知**写“晨充只读查询通过：[时间]”。不匹配时显示“晨充只读查询未通过”，不要显示成功通知。

创建一个“特定时间”个人自动化，设为当前时间之后 **3–5 分钟**，运行“晨充只读测试”。按当前 iOS 的界面选择“立即运行”，或关闭“运行前询问”。如有“锁定时允许运行”选项，按手机界面启用；不同系统版本的入口可能不同。

先退出快捷指令并锁屏。到时间后，记录是否收到成功通知、通知中生成的实际时间、是否要求解锁或确认。再在实际停车地点使用蜂窝网络复测。测试完成后停用这条测试自动化，避免它每天查询。

Apple 明确把“特定时间”列为可不询问自动运行的触发条件，也说明单个操作可能需要另外设置，见[官方自动化说明](https://support.apple.com/zh-cn/guide/shortcuts/apd602971e63/ios)。这不构成本项目在锁屏、低电量或网络变化下的实测证明。
